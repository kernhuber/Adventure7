# Zombie NPC Implementation - Progress Summary (2026-02-16)

## The Plan

The goal is to add a fully autonomous, LLM-driven **Zombie NPC** to the German-language text adventure game. The zombie starts as a skeleton (`o_skelett`) in the cave and comes to life when the player interacts with the wallet (`o_geldboerse`). Once awakened, the zombie:

- **Hunts the player** autonomously using a "notebook" pattern where a reasoning LLM (Gemini 2.5 Flash) makes strategic decisions each turn, maintaining its own notes
- **Can be talked to** via the existing dialog system, responding in-character as a deceased businessman (Herbert Kronstein) speaking broken German
- **Can be convinced to cooperate** through dialog, transitioning from hostile to cooperative
- **Enables a cooperative puzzle** where two switches in separate rooms (Kontrollraum + Generatorraum) must be activated simultaneously by player and zombie
- **Has dual resolution paths**: cooperative (true win with zombie redemption) vs aggressive (hollow victory)

The plan is structured in 5 phases: Data Layer, NPCZombieState Core, Game Loop Integration, Dialog Enhancement, and Win/Lose Conditions.

## Bugs Found and Fixed During Testing

| Bug | Root Cause | Fix |
|-----|-----------|-----|
| `'NoneType' object is not callable` on `interagieren` | Three sub-issues: (1) `interagieren` not in intercept list, (2) wrong dict key `.get("command")` vs `func_name`, (3) `["firstmessage"]` KeyError | Added `interagieren` to all 3 intercept points, used `func_name` variable, changed to `.get()` |
| All commands fail with "Interne Befehlsstruktur konnte nicht interpretiert werden" | Gemini wraps JSON responses in markdown code fences (` ```json...``` `), causing `json.loads()` to fail | Strip markdown fences before JSON parsing in `GeminiInterface.py` |
| Zombie dialog returns "nichts" silently | `type(pl) is not PlayerState` compared against the **module** instead of the **class** `PlayerState.PlayerState` | Changed to `isinstance()` checks with `hasattr` guards |
| Zombie icon not appearing in GUI | Browser caching old HTML without new `<script>` tag | Added no-cache HTTP headers + embedded overlay function inline in `websockets.js` as fallback |
| EC card obtainable before zombie awakens | `o_geldboerse_reveal_f` was unhiding EC card on examine | Removed EC card reveal; card only exists in zombie's inventory after awakening |
| Zombie not awakening on take (only on examine) | Awakening logic was in `reveal_f` only | Created shared `_awaken_zombie()` helper called from both `reveal_f` and `take_f` |
| `'LLMClientGemini' object has no attribute 'client'` | `gs.llm` is the adapter wrapper; actual client is at `gs.llm._impl` | Fixed `_call_reasoning_llm()` to use `gs.llm._impl.client`, `.tokens`, `.numcalls`, etc. |
